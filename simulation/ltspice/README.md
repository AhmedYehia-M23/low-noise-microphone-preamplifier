# LTspice simulations

The project includes two separate simulation schematics. Only the final KiCad sources represent the production PCB.

## AD8656 schematic

![AD8656 LTspice signal-path schematic](../../docs/ltspice/ltspice_schematic_ad8656.png)

*Screenshot from an earlier command configuration. For the current executable directives, use the latest `.asc` source below.*

[Microphone_Preamplifier_AD8656.asc](Microphone_Preamplifier_AD8656.asc) models the microphone preamplifier signal path with `AD8656` values assigned to both op-amp symbols. It includes the directive:

```text
.include ad8656.cir
```

To run it, download the AD8656 SPICE macro-model from [Analog Devices' official AD8656 page](https://www.analog.com/en/products/ad8656.html), name it `ad8656.cir`, and place it beside the schematic. The model is copyrighted © 2010, 2012 by Analog Devices, Inc. and references [ADI's SPICE model license](https://www.analog.com/en/license/spice-models.html). **It is not redistributed here.**

**Validation boundary:** The model was supplied separately and is not redistributed. The AC and transient results were generated by the user in LTspice; they have not been independently rerun here. The model subcircuit, pin mapping, and complete PCB hardware performance require separate verification.

The checked-in `.asc` file is a **clean, reproducible 30 dB AC-analysis baseline**, assembled from the supplied schematic and subsequent simulation settings. It retains the unchanged electrical circuit, the sine-wave current-source stimulus `I1 = SINE(250u 1u 1k)` (`AC 1u`), and just these analysis directives:

```text
.include ad8656.cir
.param Rpot=500
.ac dec 100 1 1Meg
.meas AC Gain_1k FIND db(V(audio_out)/V(mic_out)) AT=1k
.meas AC F_LOW WHEN db(V(audio_out)/V(mic_out))=26.5132 RISE=1
.meas AC F_HIGH WHEN db(V(audio_out)/V(mic_out))=26.5132 FALL=1
```

The cutoff threshold is tied to the **29.5233 dB at 1 kHz** reported for `Rpot=500 Ω`; update the threshold if the gain changes. The on-board power switch and LED are omitted from this analog signal-path model.

### Reproducing the other analyses

Keep the op-amp model include and `Rpot` parameter. Change the enabled analysis as needed; do not run AC and transient/noise analyses with unrelated `.meas` commands active.

| Analysis | Configuration |
| --- | --- |
| 40 dB AC gain | Set `.param Rpot=1`; run `.ac dec 100 1 1Meg`; plot `V(n001,vref)/V(vbias,vref)` |
| Stepped AC gain | Add `.step param Rpot list 1 179 500`; use `.ac dec 100 1 1Meg`; disable the fixed 30 dB cutoff `.meas` commands |
| 1 kHz transient | Replace `.ac` with `.tran 0 3m 0 50n`; disable the AC `.meas` commands |
| Stepped transient | Use `.tran 0 3m 0 50n` with `.step param Rpot list 1 179 500` |
| Output-noise spectrum | Replace `.ac` with `.noise V(audio_out) I1 dec 100 20 20k`; set `Rpot=500`; plot `V(onoise)` |
| Integrated output noise | Alongside the `.noise` directive, use `.meas NOISE Output_Noise_RMS INTEG V(onoise) FROM=20 TO=20k` |

| Mid-supply reference capacitor, 10 µF | C1 | C3 |
| Input coupling capacitor, 100 nF | C2 | C4 |
| Low-pass capacitor, 27 nF | C3 | C5 |

The simulation omits the production PCB's slide switch and power-indicator circuit. **Use the KiCad schematic and PCB, not LTspice reference numbers, for physical assembly.**

## AD8656 AC gain — user-run LTspice result

![AD8656 amplifier-stage AC gain, Rpot 1 ohm](../../docs/ltspice/ltspice_ac_gain_40db_ad8656.png)

The AC analysis uses `Rpot=1 Ω`. Plot `V(n001,vref)/V(vbias,vref)` directly in LTspice's AC plot window; the vertical axis already displays gain in dB. **Do not wrap this trace in `dB()`**, which would apply the logarithmic conversion twice.

The supplied simulation log reports `Input_1k = −53.5545 dBV` and `Output_1k = −13.509 dBV`; the difference is approximately **40.0455 dB at 1 kHz**. The ideal feedback network yields approximately **40.05 dB**, consistent with the reported result. These are user-run simulation results, not physical test results. The figure is only the amplifier-stage gain; it does not measure the full input-to-output high-pass and low-pass response.

## Full signal-path frequency response — user-run LTspice result

![AD8656 full signal-path AC sweep at 30 dB setting](../../docs/ltspice/ltspice_full_frequency_response_ad8656.png)

With `Rpot=500 Ω`, plot `V(audio_out)/V(mic_out)` in the LTspice AC waveform viewer (without `dB()`). The sweep shows approximately **30 dB midband gain** and both high-pass and low-pass roll-offs. The user-run SPICE Error Log reported these numeric results at `Rpot=500 Ω`:

| Measurement | Value |
| --- | ---: |
| `Gain_1k` at 1 kHz | 29.5233 dB |
| Applied gain threshold | 26.5132 dB (approximately −3.01 dB relative to 1 kHz) |
| `F_LOW` | **30.8214 Hz** |
| `F_HIGH` | **19,702.8 Hz** |
| Difference between crossings | 19,671.98 Hz |

Commands used:

```text
.meas AC Gain_1k FIND db(V(audio_out)/V(mic_out)) AT=1k
.meas AC F_LOW WHEN db(V(audio_out)/V(mic_out))=26.5132 RISE=1
.meas AC F_HIGH WHEN db(V(audio_out)/V(mic_out))=26.5132 FALL=1
```

The measured crossings are approximately 3 dB below **the 1 kHz gain**, not necessarily 3 dB below the absolute maximum of the response curve. These are user-run LTspice simulations, not physical measurements.

## Stepped AC response — three gain settings

![AD8656 stepped AC frequency response at approximately 30, 35, and 40 dB](../../docs/ltspice/ltspice_stepped_ac_gain_ad8656.png)

The user-run sweep used:

```text
.step param Rpot list 1 179 500
.ac dec 100 1 1Meg
```

Plot `V(audio_out)/V(mic_out)` directly in the LTspice AC waveform viewer. The solid curves show approximately **40 dB (green, 1 Ω)**, **35 dB (blue, 179 Ω)**, and **30 dB (red, 500 Ω)** in the midband. Dotted curves represent phase, not additional gain traces. These are simulation results, not bench measurements. Numerical −3 dB bandwidth checks are still pending.

## Stepped transient output — three gain settings

![AD8656 stepped 1 kHz transient output](../../docs/ltspice/ltspice_stepped_transient_ad8656.png)

The user-run transient sweep enabled `.tran 0 3m 0 50n` and `.step param Rpot list 1 179 500`, with `I1 = SINE(250u 1u 1k)` and AC analysis disabled.

The plotted `V(audio_out)` traces show approximately **420 mVpp** at 1 Ω (green), **235 mVpp** at 179 Ω (blue), and **130 mVpp** at 500 Ω (red). These are graph-based estimates at the 1 kHz test frequency, not physical measurements; waveform appearance alone does not quantify harmonic distortion.

## AD8656 output-noise spectrum — user-run LTspice result

![AD8656 simulated output-noise spectral density](../../docs/ltspice/ltspice_output_noise_ad8656.png)

The user-run noise sweep used:

```text
.param Rpot=500
.noise V(audio_out) I1 dec 100 20 20k
```

Plot `V(onoise)`. This trace represents the **output-referred noise amplitude spectral density** in V/√Hz, **not** integrated output RMS noise. The schematic models the microphone with an ideal current source, so it does not characterize the complete real electret capsule's self-noise. SPICE noise accuracy also depends on the noise behavior implemented in the AD8656 macro-model. The plot alone does not report integrated output RMS noise or any measured hardware noise figure.

### Integrated output-noise result — 20 Hz–20 kHz

The user also ran:

```text
.meas NOISE Output_Noise_RMS INTEG V(onoise) FROM=20 TO=20k
```

LTspice returned:

```text
output_noise_rms: INTEG(v(onoise))=3.18777e-05 FROM 20 TO 20000
```

For noise analysis, LTspice's `INTEG V(onoise)` produces an **integrated RMS noise voltage**. The result is **31.8777 µV RMS (approximately 31.88 µV RMS)** at `V(audio_out)` for `Rpot=500 Ω` over 20 Hz–20 kHz. It depends on the SPICE macro-model and source configuration, with no real microphone capsule self-noise model; **it is not a hardware measurement or a complete microphone-system noise specification**.
